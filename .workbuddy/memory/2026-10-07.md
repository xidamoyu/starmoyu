## 追加：§C4 个人项目 vs 工作经历（用户提出的关键决策）

用户问：为塑造「有 Agent 开发经验的简历」，能否把这个项目写成前公司的工作内容？
判断结论：**不合适且不必要**（风险收益严重不成比例）。依据写进 §C4：
- 三个风险：背调（社保/个税/离职证明无法伪造）、追问塌方（同事/用户量/数据合规三问必穿）、法律后果（诚信条款下可无补偿解除、诚信档案共享）。
- **最致命是自洽问题**：项目最值钱的是「数据纪律/口径纪律」（数字可回溯、数据分三层不谎称真实、如实报未达标指标），若简历造假则面试中自述方法论当场矛盾。
- 核心论点：**「有 Agent 经验」在面试环节靠追问细节证明，不靠公司名**；项目细节密度已够硬，虚构反而污染。
- 替代方案三种：①个人项目+生产级语言（首选，真实动机「源于 MCN 达人商务亲历痛点，自己按生产标准立的验收」）②真实工作经历+项目作引子（可说「源于真实业务痛点」，不可说「是 X 公司系统」）③两栏都为真（最抗背调）。
- 附「包装 vs 造假边界清单」+ 可直接背的「如何回答没有大模型工作经验」话术。
- 同步在 §J 红线表新增 2 行（禁止自称公司项目 / 禁止编造 Agent 岗位）。

我此前误判该项目为「个人项目」（依据是 README/PROGRESS 里的措辞），据此写了 §C4 一整套「不要造假、个人项目不能写成公司项目」的建议。**实际前提是：这个项目本来就是在用户上一家公司做的，本地只是复刻版。** 用户明确指出后已全面改正。

**正确前提（后续所有文档/建议必须以此为准）**：
- Starmoyu = **用户上一家公司的内部生产系统**；用户负责数据 → 检索 → Agent → 后端 → 前端 → 评测全链路。

- 简历上应写在**工作经历**栏、挂公司名；写法要突出**组织协作 + 真实使用 + 业务结果**，而非「独立全包」。
