## 三、发现的问题与下一步

1. **向量库与关系库不一致（基础设施）**：Milvus 集合 dm_chunks 比 PostgreSQL 的 chunk_meta 少 2 条（残留已删除块），向量召回带回无效块编号会导致检索器键错误。评测脚本已兜底过滤；建议执行向量库全量重建。
2. **L2 语义改写层是检索短板**：五组消融中 L2 层第 1 条命中率最高 0.700（完整管线），显著低于 L1 的 0.875；查询改写（口语到书面语归一）列为下一优先级。
3. **L3 多约束聚合层依赖融合**：纯关键词路在 L3 层第 1 条命中率仅 0.250，融合后 0.550，重排序后 0.750；该层题目多标注 recall 受上下文 4000 字符窗口限制，后续可评估窗口扩大与父块扩展的收益。
4. **忠实度未达标（0.812 < 0.90）但失分结构可解释**：主要是判分口径对归纳性表述过严与判分上下文截断，而非事实编造；判分通道欠费导致本轮由同源模型判分，数字偏乐观，恢复独立判分通道后需复测。
5. **数值保真校验规则需迭代**：商单编号、年份等标识符被误计为数值失真；应在引用块范围内比对并排除编号类标识。
6. **判分与生成通道独立性**：DashScope 通道欠费（HTTP 400 Arrearage）影响了本轮判分独立性，恢复后按设计方案门禁重测。
