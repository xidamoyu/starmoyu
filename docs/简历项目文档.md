基于 LangGraph 的对话式商单业务助手：LLM 自主调用 19 个工具完成「达人筛选 → 方案生成 → 审批流转 → 跟进记录 → 结案复盘 → 经验沉淀回流 RAG」全生命周期闭环，配混合检索（BGE 向量 + BM25 + CrossEncoder 重排）与双确认沉淀协议，验证 36 项端到端断言全绿。

## 简历项目描述（可直接贴）

**项目名**：MCN 商单资产智能助手（个人全栈项目，2026.09 – 至今）

**技术栈**：LangGraph · LangChain · FastAPI · Vue3 · PostgreSQL · Milvus · Redis(可选) · MinIO · qwen3.8/qwen-vl · BGE-M3 + BM25 + CrossEncoder

- 构建**对话式业务 Agent**：LangGraph `StateGraph` + `bind_tools` + ToolNode，LLM 自主选工具、结果回喂、多轮循环；**19 个工具**覆盖商单全生命周期（检索/建方案/审批/跟进/结案/沉淀/变更申请），FastAPI(JWT+SSE) + Vue3 前端，**41 个 API 端点、14 张 PG 表**
- 设计**知识回流飞轮**：结案复盘按「Agent 主动提醒 → 预览 → 两次确认」协议入库，案例切片**增量回流向量库**（幂等：二次入库块数不变），沉淀经验可被后续选人决策召回——商单经验从聊天记录变成可检索资产
- 实现**混合检索**：BGE 向量 + BM25 + CrossEncoder 重排，消融实验 Hit@1 **0.694** / MRR **0.788**；RAGAS 忠实度 0.705 / 相关性 0.559 / 上下文精度 0.959 / 答案相关性 0.794（2063 块口径，98 条评测集同源反查生成）
- **首响性能优化**：LangGraph 双模式流式（`messages` 增量 token 逐帧 SSE + `updates` 工具事件），首字延迟从整段生成完的 **14.5s → 热态 1.3-2.2s**（SSE 事件流计时实测）；寒暄类走「关思考链 + 不挂工具 schema」轻通道（同消息 3.6s→1.2s），业务问题保留完整推理链——**快慢分离不牺牲正确性**
- **工程化验证**：14 流程 36 断言端到端回归脚本全绿；多模态附件链路（截图 → qwen-vl 转写 → 特质抽取确认卡入库，原图 MinIO 留档可溯源）；三通道导入 + Agent 预审 + 管理员双审；三级角色权限（admin/operator/viewer）

## 面试展开点（按追问深度备料）

### 1. 为什么是「真 Agent」而不是工作流编排

- 工具选择决策权交给 LLM：`bind_tools` 把 19 个工具的签名+docstring 给模型，`_should_continue` 条件边判断 `tool_calls` 是否为空决定继续循环还是结束
- 但**写库权收归 Service 层**：LLM 只能通过工具函数触发 Service 写库，状态机校验（draft→submit→pending_review→approve）、ID 生成、留痕逻辑只写一处——LLM 幻觉或乱参数污染不了数据
- 确定性路径兜底：结案表单、审批推进提供 UI 确定性入口，Agent 路径与 UI 路径最终都走同一个 Service

### 2. 检索为什么这么配（追问 RAG 细节时）

- 语料 2086 子块（结案案例 572 / 在途跟踪单 1131 / 刊例 360 / 规则方法论 18 / 导入 5），Milvus HNSW + COSINE
- 混合检索：向量召回 + BM25 关键词（达人名/商单号等精确信号）→ CrossEncoder 重排 top-k
- 评测口径诚实：消融/RAGAS 在 2063 块时点实测；语料后续增量，指标待下次刷新——**不拿旧数字冒充现值**
- 评测集 98 条由语料同源反查生成（问题和答案都能回溯到源块）

### 3. 首响优化的完整因果链（追问性能时）

- **痛点定位**：`stream_mode="updates"` 下 agent 节点 `model.invoke()` 跑完才 yield 整条 AIMessage——SSE 名义流式、实际等 14.5s 一次性全文
- **改造**：`stream_mode=["messages","updates"]` 双消费——messages 模式逐帧 yield `AIMessageChunk` 增量；updates 只发 tool_call/tool_result 事件；updates 里的完整 AIMessage 不重复推
- **选路**：`_is_chitchat` 白名单（≤14 字、无业务信号词、无钉单、无工具历史）→ 轻通道（`enable_thinking:false` + 不 bind 工具 schema，省掉 24KB 工具定义的 prompt）；同消息实测思考开 3.6s / 关 1.2s
- **配套 bug**：入口传 `("user", text)` 元组进 state，路由判定拿不到 content——统一转 `HumanMessage` 后修复（排查过程：给节点打 spy 逐层打印 message 类型）
- **量化**：SSE 事件流计时脚本落盘 `docs/延迟实测报告-R12.md`，含冷启动 8.6s 的诚实标注与热态复测 1.9/2.2/1.3s

### 4. 数据不撒谎的纪律（展示工程素养）

- 所有数字可复现：端点数 grep `@app.` 装饰器、工具数 import 后 `len()`、语料 `count(*)`、延迟 SSE 计时脚本
- 数字过时即标注时点（「2026-09-29 实测」），旧值勘误留在文档里可追溯
- 踩过的坑全部归档：ARK reasoning 吃光 max_tokens（finish_reason=length 诊断法）、image_url 静默丢弃、前端 camelCase 与 Pydantic snake_case 契约、WSL2 闲置 15s 自休眠导致端口失联（保活窗口根治）、FastAPI 422 detail 数组渲染 `[object Object]`

### 5. 一段话演示剧本（现场 demo 用）

1. 输入「你好」→ 秒级逐字响应（对比改造前录屏/数据）
2. 「美妆类目粉丝10万以内有哪些互动率高的达人？」→ 工具折叠条先出现（search_kols），正文打字机跟进
3. 「DC20250001 现在什么情况」→ 商单状态 + ROI 表格
4. 「给雅屋建一个9万预算的美妆方案，两周内发布」→ 确认卡（本轮不写库）→「确认，建吧」→ create_proposal 落库 draft → 审批中心可见
5. 拖入聊天截图 → qwen-vl 转写 → 特质确认卡 → 确认入库 → 换会话问该达人的合作偏好 → 特质被召回（飞轮闭环）

## 已知边界（主动交代比被问倒强）

- 工具服从性偶发波动：qwen3.8-flash 偶尔对确认词不直接调工具（复现率低，方向是确认词→工具意图的确定性引导）
- 消融/RAGAS 数字是 2063 块时点，语料已增至 2086，待刷新
- 检索优化清单还有一项未做（刊例结构化路由）
- 单机部署（PG/MinIO 本机，Milvus 在 WSL Docker），未上 k8s
