## 一、一句话版本

基于 LangGraph 框架的对话式商单业务助手：大语言模型自主调用 19 个工具，完成「达人筛选 → 方案生成 → 审批流转 → 跟进记录 → 结案复盘 → 经验沉淀回流知识库」的完整业务闭环；配独立的分层评测体系（107 题、五组消融、检索增强生成评估框架四指标），检索五指标全部达标，数值保真率 100%。

## 二、简历项目描述（可直接粘贴）

**项目名称**：MCN 商单资产智能助手（个人全栈项目，2026 年 9 月至今）

**技术栈**：LangGraph · LangChain · FastAPI · Vue3 · PostgreSQL · Milvus · MinIO · qwen3.8 / qwen-vl · gte-rerank-v2 · BM25

1. **对话式智能体主链路**：使用 LangGraph 的 StateGraph 组织节点，通过 `bind_tools` 把 19 个工具的函数签名与说明文档交给大语言模型，由模型自主决定调用哪个工具、调用几次、何时结束；工具执行结果回喂模型形成多轮循环。后端 FastAPI 提供 41 个接口（JWT 鉴权 + SSE 事件流），前端 Vue3，PostgreSQL 共 14 张表。

2. **混合检索管线**：非结构化语料 2086 个文本块（结案案例 572 / 在途跟踪单 1131 / 刊例报价 360 / 平台规则与方法论 18）走「BGE 向量召回（Milvus）+ BM25 关键词召回 → 倒数排名融合 → 文档级去重 → 云端交叉编码器重排序」；结构化数据（达人 14289 条、商单 400 条）走 SQL 精确过滤，由大语言模型自主路由。独立评测集 107 题（分层构建、与语料解耦）实测：完整管线第 1 条命中率 0.750、前 5 条命中率 0.913、平均倒数排名 0.823，五项检索指标全部达到设计目标线。

3. **消融实验证据链**：五组对照（纯向量 / 纯关键词 / 融合 / 加去重 / 完整管线）逐组件归因——倒数排名融合把前 10 条召回率从 0.835 提到 0.920；重排序让精确查找层的第 1 条命中率提升至 0.938（前 5 条命中 100%），但对归纳推理层增益有限——据此提出「重排序按查询类型路由、与融合分数插值」的改进方向，用数据说话而非无脑堆组件。

4. **生成质量评估**：检索增强生成评估框架（RAGAS）四指标，判分通道与生成模型不同源（qwen-plus 独立判分）：忠实度（faithfulness）0.945、答案相关性 0.856、拒答正确率 100%、数值保真率 100%（引用块内数值与数据库原值零偏差）；失分样本逐条人工归因（真实编造 / 判分口径 / 评测伪影三类占比），据此在提示词层强约束归纳性表述的引用边界。

5. **知识回流飞轮**：商单结案后智能体主动提醒沉淀 → 案例预览 → 两次确认 → 文本切片增量回流向量库（按来源文件幂等，重建后向量库与关系库 2086 条零差异）→ 沉淀案例可被后续推荐决策召回，语料随业务运转自动增厚。

6. **首响性能优化（流式改造）**：LangGraph 双模式流式——messages 通道把模型增量文本逐帧推送到浏览器（打字机效果），updates 通道负责工具调用事件；寒暄类输入走关闭思考链、不挂载工具定义的轻量通道。实测寒暄类首字延迟从 14.5 秒降到热态 1.3 至 2.2 秒（SSE 计时脚本落盘），业务问题保留完整推理链。

7. **多模态与数据防线**：微信谈判截图拖入对话 → 视觉模型 qwen-vl-plus 完整转写 → 智能体抽取合作特质（附原文引用）→ 确认卡入库、原图对象存储留档；三类外部数据统一进暂存区，大语言模型质检预审（实测抓出负预算脏数据）+ 管理员确认后才落正式表。

8. **权限与审计**：三级角色（管理员 / 运营 / 只读）；商单资产字段变更走审批流——智能体只能创建变更申请（自动捕获旧值快照），人工批准后由服务层原子写回并留痕。

## 四、评估体系本身（也是简历亮点）

- **评测集与语料解耦**：107 题从业务视角独立出题、以文档为单位标注相关档位（直接回答 / 部分辅助），全部标注经语料存在性校验；避免「从语料抄答案再问语料」的自证偏乐观。
- **难度分层报告**：精确查找 / 语义改写 / 多约束聚合 / 否定式拒答四层分别出报告，不用总平均掩盖弱项——实测发现语义改写层是短板（0.650 对 0.938），查询改写列为下一优先级。
- **判分独立性**：生成质量判分用与生成模型不同源的判分通道；失分样本逐条人工复核并给出三类归因占比（真实编造 / 判分口径 / 评测伪影），不把结构性偏差误判为质量缺陷。
- **比对规则可修正**：数值保真初版规则把商单编号误判为数值失真，修正为「仅引用块比对 + 排除标识符」后核验，规则演进全程留痕。
- **消融归因到组件**：每个组件（融合、去重、重排序）的贡献由对照实验单独量化，重排序的分层分化也被如实报告并转化为路由改进方案。

## 五、已知边界（主动交代）

1. 重排序在归纳推理层增益有限，改进方向（按查询类型路由 / 与融合分数插值）已明确但未实施。
2. 语义改写层第 1 条命中率 0.650 低于精确查找层，查询改写（口语到书面语归一）是下一优先级。
3. 忠实度失分中约半数是归纳性表述超出检索依据的真实编造，集中在归纳题，提示词强约束已列为行动项。
4. 单机部署（PostgreSQL 本机、Milvus 在 Windows 子系统的 Docker 中），未上容器编排。
