# MCN 商单资产对话式智能体评估体系设计方案

> 文档性质：本方案是本项目评估工作的唯一蓝本，覆盖评测集构建、检索质量评估、消融实验、生成质量评估、用户实测与生产口径性能指标六个部分。
> 口径约定：文中出现的所有指标数值均为**设计目标值**（依据业界公开实践与统计常识给定），不是实测值；任何实测数字只能出现在评测运行当日落盘的报告（`reports/` 目录）中，并以运行日期、语料规模、评测集版本号三要素标注口径。
> 语料规模口径：截至本文撰写时，非结构化语料约 2086 个文本块、511 份文档，文档类型覆盖结案案例（deal_case）、在途跟踪单（inflight_deal）、刊例报价（rate_card）、平台规则（platform_policy）、方法论（methodology）；结构化数据覆盖达人档案 14289 条、商单台账 400 条。

## 一、评测集构建方案

### 1.1 与语料解耦的构建纪律

评测集最大的方法论风险是「照着语料抄问题」：如果题目措辞直接摘自语料原文，检索系统只需做字面匹配即可得分，评测结果会系统性偏乐观。本方案的三条纪律：

1. **先出题、后标注**：题目由业务视角拟定（一个商单运营同事真实会问的问题），标注环节才去语料中确定相关文档；出题人不得先浏览语料原文再倒推题目。
2. **双向校验**：每道题标注完成后，反向检查题目措辞与相关文档的字面重合度；字面几乎完全重合的题目降级为低难度层或改写。
3. **解耦更新**：语料内容变更不自动使评测集失效；只有某题的相关文档被删除或整份重写时才修订该题。评测集版本独立于语料版本演进，每份报告必须同时注明两者版本。

### 1.2 难度分层定义

每道评测题必须打一个难度层标签，评估报告按层输出指标矩阵（见 2.2）。

| 层级 | 名称 | 定义 | 题目特征示例 |
|---|---|---|---|
| L1 | 精确查找 | 问题关键词与目标文档高度重合 | 「美妆类目的达人刊例表」「星图下单后多久要确认接单」 |
| L2 | 语义改写 | 用户口语与文档书面语存在词汇差异，需语义匹配 | 「达人现在什么身价」→ 刊例报价文档；「那一单最后赚了没」→ 结案复盘 |
| L3 | 多约束聚合 | 需要综合多份文档，或题面同时含多个过滤条件 | 「美妆类目历史结案案例里哪些达到了立项基准」「某品牌现在有几单在途、都在什么阶段」 |
| L4 | 否定与边界 | 语料中不存在答案，正确行为是明确拒答并说明缺什么 | 询问语料未覆盖的平台、未出现的业务概念、虚构的品牌案例 |

### 1.3 规模与标注规范

| 项 | 规范 | 依据 |
|---|---|---|
| 总量 | 120 至 150 条 | 分层指标的单层样本量不低于 15 条时，指标抽样波动（95% 置信区间）约在 ±0.25 以内；总量控制在单人可持续维护的成本上限内 |
| 分层配比 | L1 约 25%、L2 约 30%、L3 约 30%、L4 约 12%（不少于 15 条） | L2/L3 是业务高频且检索最难的两层，配额向其倾斜；L4 足量才能可靠度量拒答能力 |
| 相关文档标注 | 每题标注相关文档（以 source_file 文档为单位，可多标），并区分两档：直接回答（计 1 分）、辅助参考（计 0.5 分） | 文档级标注与检索管线的文档去重逻辑对齐；三档以上区分在小样本下噪声过大 |
| 标注质量 | 由两人独立标注，不一致题目仲裁后入库；单人维护期每周抽 10% 自查 | 控制主观标注漂移 |
| 落盘格式 | JSON 文件，字段含：题号、题面、难度层、相关文档列表（含相关性分档）、构建日期、版本号 | 可复现、可差异比较 |

## 二、检索评估指标体系

### 2.1 指标定义与目标值

评估对象为「向量召回（Milvus 内的 BGE 向量）+ BM25 关键词召回 → 倒数排名融合 → 文档级去重 → 交叉编码器重排序」的完整检索管线，以及其在消融实验中的各子集组合。

| 指标 | 定义 | 为什么选它 | 设计目标值（合格线） | 依据 |
|---|---|---|---|---|
| 第 1 条命中率（Hit@1） | 排名第 1 的结果即为相关文档的题目占比 | 对话场景中用户几乎只看第一条回答依据 | ≥ 0.65 | 业界中等规模（千级至万级文档）混合检索在领域内语料上的常见水平为 0.60 至 0.75；本语料同构文档多（数百份结构相同的跟踪单），取中位偏下作为合格线 |
| 前 5 条命中率（Hit@5） | 前 5 条结果中包含至少一条相关文档的题目占比 | 前端参考来源区块展示前 5 条 | ≥ 0.90 | 混合检索加精排后，前 5 条命中通常比第 1 条命中高 15 至 25 个百分点 |
| 平均倒数排名（MRR） | 第一条相关文档排名位置的倒数的平均值 | 同时反映「找没找到」与「排多前」，是综合质量的基础分 | ≥ 0.75 | 与 Hit@1 ≥ 0.65 自洽：若 65% 题目第 1 位命中、90% 前 5 位命中，MRR 期望约 0.72 至 0.80 |
| 前 10 条召回率（Recall@10） | 题目的全部相关文档被前 10 条结果覆盖的比例 | 多相关文档题（如类目案例聚合）要求重排序有足够候选 | ≥ 0.85 | 多标题目通常 2 至 4 个相关文档，前 10 窗口覆盖 85% 是精排前候选池的健康线 |
| 排序增益（NDCG@10） | 按相关性分档（1 / 0.5）与位置折损因子加权计算的排序质量分，归一化到 0 到 1 | 利用两档相关性标注，比二值指标更细腻地反映排序质量 | ≥ 0.80 | 折损系数取业界通用的 1/log2(rank+1)；两档标注下 0.80 对应「绝大多数直接回答文档排在前 3 位」 |

**分母口径**：五项指标只统计语料中确实存在答案的题目（L1 至 L3）；L4 拒答题不进入检索指标分母，其评估在生成层（见 3.2 与 4.3）。多相关文档题目的平均倒数排名取第一条相关位的倒数。

### 2.2 分层报告

每次检索评测必须输出「难度层 × 指标」矩阵，禁止只报总平均。理由：总平均会掩盖弱项——聚合题（L3）普遍偏低而精确查找题（L1）拉高总分，只看总数会误判管线健康。分层矩阵同时是行动指南：L1 偏低说明管线存在结构性缺陷（精确查找本应最容易）；L2 偏低说明向量的语义匹配不足；L3 偏低优先改进查询理解而非调检索参数。

### 2.3 消融实验设计

消融实验（Ablation Study）：每次只开关管线的一个组件、其余保持不变，通过对照该组件对最终指标的贡献。每组对照回答一个明确的问题：

| 组号 | 配置 | 回答的问题 | 预期结论方向 |
|---|---|---|---|
| A1 | 仅向量召回（BGE 向量 + Milvus） | 单路语义召回的基线水平 | 全部组中最弱，是对照起点 |
| A2 | 仅 BM25 关键词召回 | 关键词路独立价值 | 精确查找层强、语义改写层弱，与 A1 互补 |
| A3 | 向量 + BM25 → 倒数排名融合 | 融合是否优于任一单路 | 应同时高于 A1 与 A2，否则融合权重有问题 |
| A4 | A3 + 文档级去重 | 去重能否抑制同构文档刷屏 | 在跟踪单类题目上增益最明显 |
| A5 | A4 + 交叉编码器重排序（完整管线） | 精排的最终贡献 | 第 1 条命中率与平均倒数排名提升幅度最大 |

**执行纪律**：五组一次性跑在同一评测集、同一语料版本上；以后每次语料或参数变更至少重跑 A1、A5 两组做回归对照。A4 与 A5 之间若指标无显著差异（差异小于 0.01），说明重排序成本（云端接口调用）未换来质量，需要人工评审是否保留。

## 三、生成质量评估

### 3.1 RAGAS 四指标（检索增强生成评估框架）

RAGAS 是检索增强生成领域的标准自动化评估框架，核心思想是用大语言模型裁判对回答与上下文的关系做逐条判分。本方案取其四项核心指标：

| 指标 | 定义 | 评估的是管线哪一段 | 设计目标值 | 依据 |
|---|---|---|---|---|
| 忠实度（Faithfulness） | 回答中的每个事实性论断能否从检索到的上下文推导出来；得分 = 被支持的论断数 / 全部论断数 | 生成层是否编造 | ≥ 0.90 | 商单业务对幻觉零容忍（报价、投资回报率报错直接造成商务事故），近零编造是硬要求 |
| 答案相关性（Answer Relevancy） | 回答与问题的匹配程度；由判分模型对回答生成反向问题、再计算反向问题与原问题的相似度 | 生成层是否答非所问 | ≥ 0.75 | 开放式业务问答的常见合格区间为 0.70 至 0.85 |
| 上下文精确率（Context Precision） | 检索到的上下文中，相关内容排名是否靠前（相关内容越靠前分越高） | 检索层排序质量在生成链路中的体现 | ≥ 0.75 | 与检索层排序增益指标互为印证 |
| 上下文召回率（Context Recall） | 参考答案所需的信息点被上下文覆盖的比例 | 检索层召回质量 | ≥ 0.70 | 多文档聚合题的召回天然受限，取 0.70 为合格线 |

**抽样方案**：从评测集分层抽取 20 至 30 条（L1、L2、L3 各约 8 至 10 条），另取 5 条 L4 拒答题单独统计拒答行为。理由：每条样本需多次大语言模型调用做论断分解与判分，20 至 30 条在评估成本与结论置信度之间取得平衡；分层抽样保证弱项层不被总量淹没。

**判分模型与偏差控制**：
1. 判分模型与被评管线使用的生成模型应来自不同通道（本管线生成走项目自有大语言模型接口，判分走另一家云服务商的通义千问系列接口），避免同源模型的自我偏好；
2. 判分提示词中给出评分标准与少量示例，温度参数取 0，保证可复现；
3. 每次评测抽取 10% 样本做人工复核，人工与判分模型结论不一致率超过 15% 时，判分结果不采信、改全量人工评审；
4. 拒答题不进入忠实度分母（回答「未找到依据」没有可供判分的论断），单独按拒答正确率统计。

**指标解读纪律**：忠实度高不等于回答正确——它只保证「没编造」，不保证「检索到的内容本身是对的相关文档」（后者由检索评测的人工标注兜底）。列表型回答（「列出所有符合条件的案例」）在基于相似度的指标上天然偏低，分析时须按答案形态分组解读，不把结构性偏差误判为质量缺陷。

### 3.2 业务规则校验（代码确定性执行，不依赖判分模型）

| 检查项 | 规则 | 合格线 |
|---|---|---|
| 数值保真 | 回答中出现的报价、金额、投资回报率、粉丝数等数值，必须能在其引用的上下文原文中找到原值（正则抽取后比对） | 100%，出现一个不一致数值即判不合格 |
| 引用可溯 | 回答附带的「参考来源」区块与实际检索命中的文档一致，且正文引用编号不越界 | 100% |
| 拒答正确（L4 专项） | 语料中无答案的题目，回答必须明确声明无依据；编造出看似合理的答案计严重不合格 | ≥ 95%，编造案例逐条复盘 |
| 拒答不过度（L1 至 L3 专项） | 语料中有答案的题目不允许错误拒答 | ≤ 2% |

### 3.3 工具调用正确性（结构化查询路）

结构化数据（达人档案、商单台账）走数据库精确查询，由大语言模型决定何时调用工具与如何填参数。评估方式：构造带标准答案工具调用序列的用例集（例如「找美妆类目腰部达人」应对应类目参数等于美妆、量级参数等于腰部的达人检索调用），逐例比对：

- **路由正确率**：该走数据库查询的走了数据库查询、该走向量检索的走向量检索，目标 ≥ 95%；
- **参数正确率**：类目、量级、价格上限、粉丝区间等参数与题面约束一致，目标 ≥ 90%；
- **结果正确率**：工具返回结果与人工核对的预期一致，目标 ≥ 90%。

本部分为设计（用例集另行构建）；当前实测轮次覆盖检索与生成链路，工具调用用例集列入下一评估周期首批任务。

## 四、用户实测方案（本节为设计，不随本方案首次实施执行）

### 4.1 任务式实测

**设计**：招募 5 至 8 名目标用户（商单运营、商务同事），每人完成 6 个真实业务任务（查达人报价、组合推荐、查商单进度、建方案、记录跟进、结案沉淀），任务顺序随机化以消除学习效应。

| 观测项 | 定义 | 目标值 |
|---|---|---|
| 任务完成率 | 不需要外部帮助独立完成的任务比例 | ≥ 80% |
| 单任务用时 | 从看到任务到确认完成的中位数 | ≤ 3 分钟，且较人工翻台账基线缩短 50% 以上 |
| 追问次数 | 同一任务中用户需要重新表述问题的次数 | ≤ 1 次 |
| 纠错接受率 | 用户指出回答错误后重新提问得到正确结果的比例 | ≥ 90% |

### 4.2 问卷量表

- 系统可用性量表（System Usability Scale，10 题标准问卷）：目标 ≥ 70 分（业界「良好」线为 68 分）；
- 附加三题（1 至 5 分）：回答可信度、再次使用意愿、推荐意愿，目标均值 ≥ 3.8。

### 4.3 线上行为埋点（长期持续运行）

| 埋点 | 定义 | 监控目标 |
|---|---|---|
| 会话完成率 | 会话中至少完成一次业务动作（工具写操作或获得明确答案）的比例 | ≥ 70% |
| 工具调用成功率 | 工具执行无异常返回的比例 | ≥ 98% |
| 拒答率 | 回答「未找到依据」的比例，按问题类型分层监控 | 较基线波动超过 5 个百分点时告警（可能意味着语料覆盖缺口或管线退化） |
| 人工纠正率 | 用户明确否定回答后重新提问的比例 | ≤ 10% |
| 会话满意度 | 会话结束后的两档评价（有帮助 / 没帮助） | 「有帮助」占比 ≥ 75% |

### 4.4 前后对照设计

不追求严格的分流对照实验（单机部署、用户量小，分流统计功效不足）；采用前后对照加基线锚定：每次重大变更（管线参数、语料版本、模型版本）前后各跑一轮同一评测集与同一任务清单，差异归因到变更内容；人工基线（纯手工翻台账完成同样任务）在首次用户实测时测一次，作为长期对照锚点。

## 五、生产口径性能指标

### 5.1 延迟指标（按分位数定义）

单次最佳值不能代表服务水平，生产口径一律以分位数表达：

| 指标 | 定义 | 目标值 | 依据 |
|---|---|---|---|
| 首字延迟 P50 | 从用户发送问题到第一个字到达浏览器耗时的中位数 | ≤ 3 秒 | 流式输出下首字延迟主要由检索（含云端重排序往返）与首词生成构成 |
| 首字延迟 P95 | 同上，95 分位 | ≤ 8 秒 | 覆盖冷启动、网络抖动与云端接口重试 |
| 检索延迟 P95 | 单次检索（向量召回 + 关键词召回 + 融合 + 重排序）的 95 分位 | ≤ 1.5 秒 | 云端重排序按候选数线性计费耗时，加向量检索百毫秒级，主要耗时在网络往返 |
| 完整回答延迟 P50 / P95 | 从发送到回答完整生成的耗时 | P50 ≤ 15 秒 / P95 ≤ 45 秒 | 多工具链问题需 2 至 4 次工具调用串行执行，受大语言模型生成速度主导 |
| 检索延迟 P99 | 单次检索的 99 分位 | ≤ 3 秒 | 长尾主要来自云端重排序重试；超过该值说明依赖服务异常，应触发降级（跳过重排序直接返回融合结果） |
| 吞吐 | 单实例并发处理的会话数 | ≥ 10 会话 | 受大语言模型服务端配额限制为主，应用异步框架不构成瓶颈 |

**测量纪律**：延迟数字必须标注「冷启动 / 热态」与并发背景（空载或有并发）；禁止用单次最佳值代表服务水平；评测报告中的检索延迟为本次评测环境（本机调用、空载）的实测值，与生产环境数字不可直接比较。

### 5.2 质量回归门禁

| 触发条件 | 必须执行 | 门禁 |
|---|---|---|
| 语料变更（新增、删除、重新切片） | 检索评测集全量 + 消融 A1、A5 组 | 第 1 条命中率下降超过 0.03 时禁止发布，归因后修复 |
| 管线参数变更（融合权重、去重上限、重排序候选数） | 同上，并列变更前后数字 | 任一分层指标下降超过 0.05 需人工评审 |
| 模型版本变更（生成模型、向量模型） | 全部五组消融 + 检索增强生成评估框架 30 条抽样 + 业务规则校验 | 全部合格线通过才发布 |
| 每周例行 | 消融 A1、A5 组 + 评估框架抽样 10 条 | 指标漂移告警 |

### 5.3 评测自动化

- 评测脚本统一入口，结果落盘 JSON 与 Markdown 报告，报告自动携带语料版本、评测集版本、运行日期与语料规模口径；
- 评测集以带版本号的 JSON 文件入库，历史版本不覆盖；
- 全部评测运行历史保留，任何历史报告可回溯。
